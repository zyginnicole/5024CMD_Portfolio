# Loan Repayment Analysis (5024CMD Data Science, Individual Assignment)


This repository holds the code, data files and prototype that accompany the report *5024CMD Portfolio*. The project asks: **to what extent can FICO score, interest rate, debt-to-income ratio and revolving utilisation predict whether a loan is fully repaid?** The outcome is `not.fully.paid` (0 = repaid, 1 = not fully repaid).

Dataset: Loan Data, 9,578 loans and 14 attributes, supplied by the lecturer.

## How to run

**Notebooks and script (Python 3.12)**

```bash
pip install pandas scikit-learn scipy statsmodels seaborn matplotlib mlxtend
jupyter notebook
```

- Keep `loan_data.csv` in the same folder as the notebooks.
- Run `loan_association_rules.ipynb` from top to bottom. Task 5 (database) uses variables created in Tasks 1 and 2.
- `sqlite3` is part of Python, so no database installation is needed. The notebook creates `loan_data.db`.
- Random seeds are fixed (sampling and train/test split: 42) so the results can be reproduced.

**WEKA (Apriori, Associate tab)**

| Run | File | Class-association rules | Min. support | Min. confidence | Max. rules |
|---|---|---|---|---|---|
| A | `loan_10.arff` | off | 0.3 | 0.8 | 30 |
| B | `loan_50.arff` | on (class = `not_fully_paid`) | 0.05 | 0.5 | 10,000 |

**Rule checker**

Open `loan_rule_predictor.html` in any web browser. It is a single file and needs no installation or internet connection. Five test cases with screenshots are in Appendix B of the report.

## Key results (see the report for details)

- 84.0% of loans were repaid and 16.0% were not, so accuracy alone is misleading and models are judged on recall, precision, F1 and AUC.
- FICO score and interest rate carry most of the predictive information. DTI and revolving utilisation add little once those two are included.
- Logistic regression was selected (AUC 0.635, recall 62.5%, precision about 21%). Its AUC advantage over the random forest is within sampling error.
- Association rules were mined from deliberately small subsets, and none predicts `Not_Paid`. The rule checker is a demonstration of the technique, not a lending tool.
